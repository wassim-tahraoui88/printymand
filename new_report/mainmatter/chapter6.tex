\section{Risk analysis}
\subsection{Governance and moderation}
Marketplace platforms require governance because users publish content, printers fulfill orders, and customers depend on reliable operations.
We addressed this risk by implementing an administration space where platform activity, users, roles, ranks, and content status can be supervised.

\subsection{Authorization control}
As the number of features increases, access control becomes more important.
We applied role-based authorization consistently so that customer, designer, printer, and administrator operations remain separated.
This protects sensitive actions such as rank changes, account suspension, health checks, and fulfillment updates.

\subsection{Operational workflow consistency}
Designer analytics, printer fulfillment, customer tracking, and administrator metrics all depend on consistent data.
We designed the workflow so that each user action updates the relevant indicators and preserves the relation between users, designs, products, printers, and orders.

\subsection{Maintainability}
The platform was organized with reusable components, centralized services, modular API layers, repository contracts, and structured database migrations.
This organization reduced complexity and made the system easier to extend.

\section{Development}
\subsection{Customer dashboard}
The customer dashboard allows users to view their orders, manage profile data, save addresses, define payment preferences, and consult submitted reviews.
This workspace gives customers a clear view of their activity on the platform.

\reportfigure{customer-dashboard}{figures/screenshots/customer-dashboard.png}{Customer dashboard interface screenshot.}

\subsection{Designer dashboard}
The designer dashboard supports design management and analytics.
Designers can create or update designs, define design status, assign products to artworks, and configure product-specific placement defaults.
The dashboard also displays performance indicators such as earnings, number of designs, order count, and conversion.

The design model includes title, image, designer information, category, description, tags, rating, sales, views, engagement rate, conversion rate, price, status, assigned products, product configurations, and timestamps.

\reportfigure{designer-dashboard}{figures/screenshots/designer-dashboard.png}{Designer dashboard interface screenshot.}

\subsection{Printer dashboard}
The printer dashboard allows printing partners to manage products and incoming order lines.
Printers can update fulfillment statuses such as pending, accepted, printing, shipped, delivered, and rejected.
The dashboard also displays product count, revenue, fulfillment rate, and rating.

The product model includes printer identity, name, category, description, base price, colors, sizes, images, availability, lead time, rating, total orders, and assigned design identifiers.

\reportfigure{printer-dashboard}{figures/screenshots/printer-dashboard.png}{Printer dashboard interface screenshot.}

\subsection{Admin dashboard}
The admin dashboard provides an overview of users, orders, revenue, active designs, and active printers.
It also supports account supervision operations such as role updates, rank updates, and account suspension.
This dashboard provides the governance layer required for a marketplace with multiple stakeholders.

For technical monitoring, the health module checks server memory and PostgreSQL connectivity.
This gives administrators visibility over essential platform health indicators.

\reportfigure{admin-dashboard}{figures/screenshots/admin-dashboard.png}{Admin dashboard interface screenshot.}

\subsection{Back-end optimization and technical services}
We added several technical services to improve reliability and maintainability:

\begin{itemize}
    \item \textbf{Validation:} incoming requests are validated through DTOs and a global validation pipe.
    \item \textbf{Exception handling:} global filters standardize error responses.
    \item \textbf{Logging:} an interceptor records request and response behavior.
    \item \textbf{Throttling:} request-rate limits protect the API from abusive usage.
    \item \textbf{Transactions:} transaction handling preserves database consistency during sensitive operations.
    \item \textbf{Realtime services:} realtime services support notifications, presence, and live updates.
\end{itemize}

\subsection{Database consolidation}
The database schema supports the main marketplace entities.
Users are separated from designer and printer inventories.
Designs can belong to albums and tags.
Products belong to printer inventories.
Orders contain order items associated with products and designs.
This model provides a coherent foundation for the full marketplace workflow.

\section{Validation and evaluation}
At the end of Cycle 3, the platform included the operational spaces required by customers, designers, printers, and administrators.
The dashboards validated the multi-role nature of Printymand, while the technical services strengthened security, monitoring, and maintainability.
This cycle completed the platform by connecting commercial workflows to governance and administration.

\section{Conclusion}
The third Spiral cycle added governance, role-specific workspaces, administration, monitoring, and optimization to Printymand.
It completed the platform by providing each actor with the tools required to participate in the marketplace.
The final conclusion summarizes the work achieved and presents perspectives for future enhancement.
